# 4WP Drive 1.5.0

**Published:** 2026-09-09  
**WordPress.org:** https://wordpress.org/plugins/4wp-drive/

## Summary

GitHub Markdown is a live Incoming source. Drive packages accept Markdown. Analytics stores import history (folder alias ↔ site slug) with Restore to incoming.

## Highlights

### For editors

- **Incoming** — same editorial queue + workspace; Drive and GitHub tabs are live.
- **Markdown packages** — subfolder with `.md` + images (Drive also still takes Google Docs and Word).
- **Image pin** — place package images in the preview before import.
- **Analytics** — history of imports: source, date, post, folder alias, site slug, incoming → published.
- **Restore to incoming** — move a published package back to the queue without rebuilding it from WordPress.

### For site owners

- **GitHub PAT** — connect one repo. Prefer a fine-grained token on that repository (Contents: Read and write). Classic `repo` tokens can reach every repo the GitHub user can access; 4WP Drive only uses the configured owner/repo.
- History table is created on the next admin load. No plugin reactivation required.
- Tested up to **WordPress 7.1**.

## Longer post (blog / newsletter)

**4WP Drive 1.5.0** keeps the Incoming dashboard from 1.4.0 and adds a second live source: **GitHub**. Put Markdown packages in `incoming/`, sync, preview, import — the plugin commits the same folder tree to `published/`. Google Drive still takes Google Docs, Markdown, and Word.

**Analytics** is the import ledger: source, post ID, folder alias, site slug, incoming and published paths. If you delete the WordPress post, **Restore to incoming** sends the package back. We do not reverse-engineer content out of Gutenberg.
